# Feature Specification: 去識別化流程的 UI／UX 簡化

**Feature Branch**: `003-ux-simplification`

**Created**: 2026-09-26

**Status**: Draft

**Input**: User description: "從 UI／UX 角度檢視後的 10 項調整：合併下載文件與編碼表、預覽反映實際輸出、保留設定只剩一個入口、模式改名並附範例、輸出方式面板收合、類別控制合併、工具列精簡、提示合併為狀態列、警告一律行內顯示、共用編碼可隨時切換。"

延伸 `specs/002-partial-retention-shared-codes`；本規格與 002 衝突之處（FR-004、FR-012、FR-022、FR-035 的逐筆選擇與鎖定行為）以本規格為準。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 一鍵下載，不會拿到對不上的編碼表 (Priority: P1)

一般使用者上傳檔案、看過預覽後只想按一個「下載」。系統一次給出去識別化文件與對應編碼表；就算使用者之後切換輸出方式，也不會出現「文件是新的、編碼表是舊的」而無法還原的情況。

**Why this priority**: 這是唯一會造成資料無法還原的 UX 缺陷。

**Independent Test**: 處理一份文件後按「下載」，確認同時取得 `.deid` 文件與 `.mapping.csv`，兩者可互相還原；切換輸出方式後只下載文件，確認出現「編碼表需重新下載」提示。

**Acceptance Scenarios**:

1. **Given** 已處理一份文件，**When** 按主要按鈕「下載」，**Then** 依序下載去識別化文件與編碼表，兩者皆標記為已下載。
2. **Given** 使用者已下載編碼表後又改變了輸出方式、取消或新增項目，**When** 只下載文件，**Then** 系統提示先前的編碼表已不適用，需重新下載編碼表。
3. **Given** 多個檔案，**When** 檢視工具列，**Then** 主要按鈕為「打包下載全部」，單檔下載移到「更多」選單。

---

### User Story 2 - 預覽長什麼樣，下載就長什麼樣 (Priority: P1)

使用者在預覽看到的，就是下載檔中的樣子（只是把編碼換成類別名稱）：全部隱藏時顯示 `[姓名]`，部分保留時顯示 `A12[身分證]9`。滑鼠停留仍可看到原文與完整輸出標記。

**Why this priority**: 預覽與輸出不一致是使用者提出「保留預覽資訊」需求的根源，也會讓人誤判交出去的內容。

**Independent Test**: 在三種輸出方式下，比對預覽標記文字與下載檔對應位置，除了編碼被類別名稱取代外完全相同。

**Acceptance Scenarios**:

1. **Given** 輸出方式為全部隱藏，**When** 檢視預覽，**Then** 每筆顯示為 `[類別]`，不再顯示 `王OO` 之類的遮罩。
2. **Given** 部分保留，**When** 檢視預覽、偵測清單與點擊標記的視窗，**Then** 都顯示「保留前綴＋[類別]＋保留後綴」。
3. **Given** 任何輸出方式，**When** 滑鼠停在標記上，**Then** tooltip 顯示類別、原文與含編碼的實際輸出標記。
4. 「顯示實際輸出標記」勾選框移除。

---

### User Story 3 - 一個地方看懂並設定輸出 (Priority: P2)

處理頁只有一個「輸出方式」區塊，平常收合成一行摘要（例如「輸出方式：全部隱藏・48 筆」）。展開後可以：選三種模式之一（全部隱藏／部分保留／自訂，各附固定範例）；在類別表中逐類別開關、看筆數、（自訂時）設定保留方式並即時看到範例；把自訂結果「設為預設」；設定整批共用編碼與匯入編碼表。

**Why this priority**: 解決「設定分散三處」與「預覽上方被面板佔滿」，是主要的簡化。

**Independent Test**: 不離開處理頁，完成「身分證保留前 2 碼、市話整類不處理、設為預設」，重新整理後自訂模式預設帶入身分證前 2 碼。

**Acceptance Scenarios**:

1. **Given** 開始處理，**When** 看預覽上方，**Then** 只有一行輸出方式摘要，點擊才展開。
2. **Given** 展開的面板，**When** 檢視模式選項，**Then** 名稱為「全部隱藏」「部分保留」「自訂」，各附一個固定範例（`A123456789 → [身分證]`、`A12[身分證]9`、逐類別設定）。
3. **Given** 類別表，**When** 取消勾選某類別，**Then** 該類別所有項目取消去識別化（取代原本的圖例色塊整批取消）。
4. **Given** 自訂模式下調整了類別保留方式，**When** 按「設為預設」，**Then** 設定寫入瀏覽器，之後的自訂模式預設帶入；規則頁「保留」欄顯示對應的唯讀文字。
5. **Given** 設定有錯誤或風險，**When** 調整時，**Then** 錯誤與警告直接顯示在該列，不使用瀏覽器彈窗。
6. 手動圈選新增的項目沿用所屬類別的保留設定，新增視窗不再有逐筆保留選單。

---

### User Story 4 - 共用編碼隨時可切換 (Priority: P3)

使用者在處理過程中才發現需要跨檔案共用編碼，或想匯入上個月的編碼表。可以直接在輸出方式面板切換或匯入，系統重新配置所有檔案的編碼，並提示需重新下載。

**Why this priority**: 進階功能，但目前「開始後鎖住」的限制讓人必須重來。

**Independent Test**: 載入兩個都含「王小明」的檔案後才開啟整批共用，確認兩檔編碼變成相同；再匯入一份編碼表，確認相同的值沿用匯入的編碼。

**Acceptance Scenarios**:

1. **Given** 已處理多個檔案，**When** 開啟或關閉整批共用編碼，**Then** 所有檔案的編碼重新配置，偵測結果、取消與手動新增皆保留，所有檔案標記為需重新下載。
2. **Given** 已處理檔案，**When** 匯入或移除編碼表，**Then** 同上重新配置。

---

### User Story 5 - 工具列與提示變安靜 (Priority: P3)

工具列只保留：重新偵測、換一個檔案（全部清除）、主要下載按鈕、「更多」選單（只下載文件、只下載編碼表、複製文字、下載合併編碼表、單檔下載等）。狀態資訊合併為一行：編碼表提醒、輸出方式、編碼範圍、格式限制（以 ⓘ 滑鼠停留顯示）；只有「含部分保留欄位」以警示色另外顯示。

**Acceptance Scenarios**:

1. **Given** 單一 Word 檔、全部隱藏，**When** 檢視工具列，**Then** 可見按鈕不超過 4 個（重新偵測、換一個檔案、下載、更多）。
2. **Given** 部分保留且整批共用，**When** 檢視狀態列，**Then** 一行顯示「全部資訊」，另一個警示提示列出部分保留類別。

### Edge Cases

- 瀏覽器可能對一次下載兩個檔案詢問權限：「更多」選單保留分開下載的選項。
- 某類別在自訂表中被關閉（不處理）時，其保留設定控制項停用。
- 「設為預設」只寫入有覆寫的類別；該類別的所有規則都套用同一個保留設定。
- 切換共用編碼或匯入編碼表時若有未下載的結果，直接重新配置並提示，不跳確認視窗（資料仍在畫面上，可重新下載）。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 主要下載動作 MUST 一次產生去識別化文件與編碼表（多檔時為打包 ZIP）。
- **FR-002**: 系統 MUST 追蹤每份文件內容的版本；單獨下載文件或編碼表時，若另一份已下載的檔案版本不同，MUST 提示需要重新下載該檔。
- **FR-003**: 預覽、偵測清單、標記視窗 MUST 以「保留前綴＋[類別]＋保留後綴」顯示；tooltip MUST 顯示含編碼的實際輸出。
- **FR-004**: 「顯示實際輸出標記」與圖例色塊列 MUST 移除；「純文字檢視」移到預覽標題列。
- **FR-005**: 輸出方式模式 MUST 命名為「全部隱藏」「部分保留」「自訂」，各附固定範例；類別內的「同預覽遮罩」選項改名為「部分保留（標準）」。
- **FR-006**: 輸出方式區塊 MUST 預設收合為一行摘要，顯示目前模式與生效筆數。
- **FR-007**: 展開後的類別表 MUST 包含：啟用勾選、類別、筆數、保留方式（僅自訂模式可編輯，其他模式顯示實際套用的方式）、範例輸出、行內錯誤與警告。
- **FR-008**: 自訂模式 MUST 提供「設為預設」，把各類別覆寫寫入規則設定；規則頁「保留」欄 MUST 改為唯讀顯示並說明到處理頁設定。
- **FR-009**: 手動新增 MUST 沿用類別設定，不提供逐筆保留選單。
- **FR-010**: 整批共用編碼與匯入編碼表 MUST 可在處理中切換；切換後 MUST 重新配置所有檔案的編碼並標記需重新下載。上傳前的進階選項保留。
- **FR-011**: 工具列 MUST 精簡為：重新偵測、換一個檔案／全部清除、主要下載、「更多」選單。
- **FR-012**: 狀態資訊 MUST 合併為一行，格式限制以 ⓘ 提示呈現；部分保留提示以警示樣式另外顯示。
- **FR-013**: 與保留設定相關的警告 MUST 以行內方式顯示，不使用瀏覽器原生彈窗。
- **FR-014**: 手機寬度（375px）下 MUST 無水平捲動，「更多」選單不超出畫面。

### Key Entities

- **文件版本（Doc Version）**：每次項目、輸出方式或編碼範圍改變時遞增；記錄文件與編碼表各自下載時的版本。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 「上傳 → 下載可還原的一組檔案」的主流程只需 2 次點擊（選檔、下載）。
- **SC-002**: 三種輸出方式下，預覽標記文字與下載檔內容除編碼外 100% 一致。
- **SC-003**: 保留設定只有一個可編輯入口。
- **SC-004**: 單檔處理時工具列可見按鈕從最多 6 個降到 4 個。
- **SC-005**: 全部既有測試通過，round-trip 還原仍 100% 正確。

## Assumptions

- 一次觸發兩個下載在主流瀏覽器可行（可能出現一次「允許多個下載」詢問）。
- 規則頁的保留編輯器（含套用建議）移除；內建建議值不再在 UI 提供，可改用「部分保留」模式一鍵取得常見保留方式。
