# Contract: 文件內編碼標記格式

去識別化文件中，被取代的內容以下列標記呈現。此格式是還原端掃描的依據，一經釋出即不可破壞性變更。

## 格式

```text
[<category>:<code>]
```

- `<category>`: 類別文字，同 CSV `category` 欄（`姓名`、`身分證`、`手機`、`市話`、`地址`、`電子郵件`、`識別碼`）。
- `<code>`: 6 字元小寫 hex（`[0-9a-f]{6}`）。
- 範例：`本案由 [姓名:a3f9c2]（身分證字號 [身分證:7b21e8]）簽署`。

## 掃描規則（還原端）

- Regex：`\[([^\[\]:]{1,10}):([0-9a-f]{6})\]`（全域）。
- 命中後以 `<code>` 查 CSV：查到 → 以 `original` 整段取代標記；查無 → 保留原樣並加入警告清單（FR-024）。
- `<category>` 不參與查表，僅供人閱讀。

## 邊界情況

- 原文中本來就存在符合此格式的文字：去識別化階段偵測到時向使用者提出警告（spec Edge Cases）；還原階段因查無 code 而保留原樣＋警告，不會誤替換。
